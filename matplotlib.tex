\begin{paracol}{2}
Visualizar los datos es fundamental para comprender y comunicar ideas e información en ciencia e ingeniería. Python no incluye funciones gráficas propias, pero hay muchas bibliotecas que las proporcionan. La más extendida es \href{https://matplotlib.org/stable/}{Matplotlib}, a la que dedicamos este capítulo.

En este curso, una gráfica tiene dos usos. El primero, \emph{entender} lo que hemos calculado: es mucho más fácil ver en una gráfica que algo va mal que en una lista de números. El segundo, \emph{convencer} a otra persona, y a nosotros mismos, de que el resultado es correcto. Volveremos sobre ello en la sección \ref{sec:graf_verif}.

Casi todo lo que vamos a usar está en el submódulo \texttt{pyplot}, que importaremos así:
\switchcolumn
Visualizing data is essential for understanding and communicating ideas and information in science and engineering. Python has no graphics functions of its own, but many libraries provide them. The most widely used is \href{https://matplotlib.org/stable/}{Matplotlib}, to which we devote this chapter.

In this course, a graph has two uses. The first is to \emph{understand} what we have computed: it is much easier to see that something is wrong in a graph than in a list of numbers. The second is to \emph{convince} someone else, and ourselves, that the result is correct. We will come back to this in section \ref{sec:graf_verif}.

Almost everything we are going to use is in the \texttt{pyplot} submodule, which we will import as follows:
\end{paracol}

\begin{minted}{python}
import matplotlib.pyplot as plt
\end{minted}

\begin{paracol}{2}
El alias \texttt{plt} es una convención: lo encontrarás en la documentación de Matplotlib y en casi todo el código que leas, incluido el que genere un asistente de IA.

\paragraph{Pyplot.}\index{Matplotlib!pyplot} \texttt{matplotlib.pyplot} es una colección de funciones que imitan la forma de dibujar de MATLAB. Cada una hace algún cambio en una figura: la crea, crea en ella un área de dibujo, traza líneas, añade etiquetas, etc. Pyplot recuerda cuál es la figura \emph{actual} y cuál es su área de dibujo actual, y cada nueva instrucción actúa sobre ellas.

\paragraph{Figuras y ejes.} Una \emph{figura} (\texttt{Figure}) es la ventana o la página en la que dibujamos. Dentro de ella hay una o varias áreas de dibujo, que Matplotlib llama \texttt{Axes}. El nombre confunde: aunque significa \emph{ejes}, cada \texttt{Axes} es una gráfica completa, con sus dos ejes de coordenadas, $x$ e $y$. En cada una podemos dibujar puntos y curvas y añadir títulos, etiquetas, leyendas, etc.

La función \texttt{figure} crea una figura nueva, vacía, a la que luego añadiremos gráficas. Admite argumentos opcionales como el tamaño en pulgadas (\texttt{figsize}), el color de fondo (\texttt{facecolor}) o \texttt{layout=\textquotesingle{}constrained\textquotesingle{}}, que ajusta los márgenes para que los títulos y las etiquetas no se solapen:
\switchcolumn
The alias \texttt{plt} is a convention: you will find it in the Matplotlib documentation and in almost all the code you read, including the code generated by an AI assistant.

\paragraph{Pyplot.}\index[eng]{Matplotlib!pyplot} \texttt{matplotlib.pyplot} is a collection of functions that mimic the way MATLAB draws. Each of them makes some change to a figure: it creates it, creates a plotting area in it, draws lines, adds labels, etc. Pyplot keeps track of the \emph{current} figure and of its current plotting area, and every new instruction acts on them.

\paragraph{Figures and axes.} A \emph{figure} (\texttt{Figure}) is the window or the page on which we draw. Inside it there are one or more plotting areas, which Matplotlib calls \texttt{Axes}. The name is misleading: each \texttt{Axes} is a complete graph, with its two coordinate axes, $x$ and $y$. In each one we can draw points and curves and add titles, labels, legends, etc.

The function \texttt{figure} creates a new, empty figure, to which we will later add graphs. It takes optional arguments such as the size in inches (\texttt{figsize}), the background color (\texttt{facecolor}) or \texttt{layout=\textquotesingle{}constrained\textquotesingle{}}, which adjusts the margins so that titles and labels do not overlap:
\end{paracol}

\begin{minted}{python}
fig = plt.figure(figsize=(4, 3), facecolor='lightskyblue',
                 layout='constrained')
\end{minted}

\begin{paracol}{2}
\textbf{¡Cuidado con los paréntesis!} \texttt{fig = plt.figure} (sin paréntesis) no crea ninguna figura: guarda en \texttt{fig} la propia función \texttt{figure}. No da ningún error; sencillamente, no ocurre lo que esperábamos.

\paragraph{¿Dónde aparecen las figuras?} En Spyder, las figuras se muestran por defecto en el panel \emph{Plots}. Para que se abran en una ventana aparte (por ejemplo, para girar con el ratón una gráfica en 3D o para ver una animación), hay que ir a \emph{Tools} $\rightarrow$ \emph{Preferences} $\rightarrow$ \emph{IPython console} $\rightarrow$ \emph{Graphics} y elegir el \emph{backend} \emph{Automatic}. Si ejecutamos un script fuera de Spyder, hay que terminarlo con \texttt{plt.show()} para que las figuras se muestren.
\switchcolumn
\textbf{Watch the brackets!} \texttt{fig = plt.figure} (without brackets) does not create a figure: it stores the function \texttt{figure} itself in \texttt{fig}. There is no error message; simply, what we expected does not happen.

\paragraph{Where do figures appear?} In Spyder, figures are shown by default in the \emph{Plots} pane. To open them in a separate window (for example, to rotate a 3D graph with the mouse or to watch an animation), go to \emph{Tools} $\rightarrow$ \emph{Preferences} $\rightarrow$ \emph{IPython console} $\rightarrow$ \emph{Graphics} and choose the \emph{Automatic} backend. If we run a script outside Spyder, we must end it with \texttt{plt.show()} for the figures to be displayed.
\end{paracol}

\section{Dibujar en 2D}
\begin{paracol}{2}
La forma más sencilla de dibujar con \texttt{pyplot} es la función \texttt{plot}\index{Matplotlib!plot}. Le pasamos dos vectores con las coordenadas $x$ e $y$ de los puntos que queremos representar, que deben tener la misma longitud.

Por ejemplo, si generamos los vectores de coordenadas
$$x=(0,2,-1,-2)$$
$$y=(0,3,2,-4)$$
y se los pasamos a \texttt{plot}, pyplot dibujará los puntos $(x,y)$ y los unirá con rectas, como puede verse en la figura \ref{fig:pyplot-simple}.

The easiest way to draw with \texttt{pyplot} is the function \texttt{plot}\index[eng]{Matplotlib!plot}. We pass it two vectors with the $x$ and $y$ coordinates of the points we want to represent, which must have the same length.

$$x=(0,2,-1,-2)$$
$$y=(0,3,2,-4)$$

t = np.linspace(0, 2*np.pi, 100)

\end{minted}

\begin{paracol}{2}
\paragraph{Scatter.}\index{Matplotlib!scatter} La función \texttt{scatter(x, y)} dibuja los puntos $(x,y)$ sin unirlos. A diferencia de \texttt{plot(x, y, \textquotesingle{}o\textquotesingle{})}, permite que cada punto tenga su propio tamaño (argumento \texttt{s}) y su propio color (argumento \texttt{c}), lo que sirve para representar una tercera magnitud. Por ejemplo, \texttt{plt.scatter(x, y, c=y)} colorea cada punto según el valor de su coordenada $y$.
\switchcolumn
\paragraph{Scatter.}\index[eng]{Matplotlib!scatter} The function \texttt{scatter(x, y)} draws the points $(x,y)$ without joining them. Unlike \texttt{plot(x, y, \textquotesingle{}o\textquotesingle{})}, it allows each point to have its own size (argument \texttt{s}) and its own color (argument \texttt{c}), which is useful to represent a third quantity. For example, \texttt{plt.scatter(x, y, c=y)} colors each point according to its $y$ coordinate.
\end{paracol}

\subsection{Varias gráficas en una figura}\index{Matplotlib!subplot}
Con la función \texttt{subplot} se pueden dibujar varias gráficas en una misma figura, dispuestas como en una tabla. Le indicamos el número de filas, el número de columnas y la posición en la que se va a dibujar la siguiente gráfica. Las posiciones se numeran desde $1$, por filas, de izquierda a derecha y de arriba abajo.

En el siguiente ejemplo se crean dos gráficas en una misma figura, en dos filas y una columna. En la primera se dibuja el coseno y en la segunda, el seno. El resultado puede verse en la figura \ref{fig:subplot_01}.
\switchcolumn
\subsection{Several graphs in one figure}\index[eng]{Matplotlib!subplot}
With the function \texttt{subplot} we can draw several graphs in the same figure, arranged as in a table. We give it the number of rows, the number of columns and the position in which the next graph will be drawn. Positions are numbered from $1$, row by row, from left to right and from top to bottom.

In the following example, two graphs are created in the same figure, in two rows and one column. The cosine is drawn in the first one and the sine in the second. The result can be seen in figure \ref{fig:subplot_01}.
\end{paracol}
\begin{minted}{python}
import numpy as np
import matplotlib.pyplot as plt
t1 = np.arange(0.0, 5.0, 0.1)
plt.figure()
plt.subplot(2, 1, 1)
plt.plot(t1, np.cos(t1), 'r.-')
plt.subplot(2, 1, 2)
plt.plot(t1, np.sin(t1), 'b.-')
\end{minted}

\subsection{Títulos, etiquetas y texto}
Con \texttt{title} se pone un título a la gráfica y con \texttt{xlabel} e \texttt{ylabel} se etiquetan los ejes. La función \texttt{text} escribe un texto en cualquier punto del dibujo: le indicamos las coordenadas (en las unidades de los ejes) y el texto.

Por ejemplo, el siguiente código da lugar a la figura \ref{fig:plot_text}.
\switchcolumn
\subsection{Titles, labels and text}
\texttt{title} puts a title on the graph, and \texttt{xlabel} and \texttt{ylabel} label the axes. The function \texttt{text} writes a text anywhere on the drawing: we give it the coordinates (in axis units) and the text.

For example, the following code produces figure \ref{fig:plot_text}.
\end{paracol}
\begin{minted}{python}
import numpy as np
import matplotlib.pyplot as plt
plt.figure()
t = np.arange(0.0, 5, 0.01)
y = np.exp(-t) * np.cos(2*np.pi*t)
plt.plot(t, y)
plt.title("Evolución de un sistema amortiguado")
plt.xlabel('t (s)')
plt.ylabel('x (m)')
plt.text(2.5, 0.8, r'$x=e^{-t}\cos(2\pi t)$')
\end{minted}

    \centering
    \includegraphics[width=0.75\linewidth]{figuras/plot_text.png}

\end{figure}

\begin{paracol}{2}
\textbf{¿Por qué la \texttt{r} delante del texto?} En una cadena normal, la barra invertida \texttt{\textbackslash} sirve para escribir caracteres especiales: \texttt{\textbackslash n} es un salto de línea y \texttt{\textbackslash t}, un tabulador. Sin la \texttt{r}, \texttt{\textquotesingle{}\textbackslash cos\textquotesingle{}} es una secuencia que Python no reconoce (se limita a dar un aviso), y en \texttt{\textquotesingle{}\textbackslash theta\textquotesingle{}} los caracteres \texttt{\textbackslash t} se convierten en un tabulador, sin ningún aviso. Las cadenas \emph{en bruto}, con una \texttt{r} delante, dejan la barra tal cual. Úsalas siempre que escribas fórmulas de \LaTeX.

\paragraph{Guardar la figura.}\index{Matplotlib!savefig} Para usar una figura en un informe, se guarda en un fichero con \texttt{savefig}. El formato se deduce de la extensión: \texttt{.png} para una imagen y \texttt{.pdf} o \texttt{.svg} para una figura vectorial, que no pierde calidad al ampliarla. Con \texttt{dpi} elegimos la resolución de las imágenes:
\begin{minted}{python}
plt.savefig('amortiguado.pdf')
plt.savefig('amortiguado.png', dpi=200)
\end{minted}
Si usamos \texttt{plt.show()}, hay que guardar la figura antes.
\switchcolumn
\textbf{Why the \texttt{r} before the text?} In an ordinary string, the backslash \texttt{\textbackslash} is used to write special characters: \texttt{\textbackslash n} is a line break and \texttt{\textbackslash t} a tab. Without the \texttt{r}, \texttt{\textquotesingle{}\textbackslash cos\textquotesingle{}} is a sequence that Python does not recognize (it only issues a warning), and in \texttt{\textquotesingle{}\textbackslash theta\textquotesingle{}} the characters \texttt{\textbackslash t} become a tab, without any warning. \emph{Raw} strings, with an \texttt{r} in front, keep the backslash as it is. Always use them when writing \LaTeX\ formulas.

\paragraph{Saving the figure.}\index[eng]{Matplotlib!savefig} To use a figure in a report, we save it to a file with \texttt{savefig}. The format is taken from the extension: \texttt{.png} for an image and \texttt{.pdf} or \texttt{.svg} for a vector figure, which does not lose quality when enlarged. With \texttt{dpi} we choose the resolution of images:
\begin{minted}{python}
plt.savefig('amortiguado.pdf')
plt.savefig('amortiguado.png', dpi=200)
\end{minted}
If we use \texttt{plt.show()}, the figure must be saved before it.
\end{paracol}

\begin{paracol}{2}
\subsection{Dos formas de trabajar: pyplot y objetos}\label{sec:ax_interface}\index{Matplotlib!interfaz orientada a objetos}
Hasta ahora hemos usado funciones de \texttt{pyplot}, que actúan sobre la figura y la gráfica actuales. Matplotlib tiene una segunda forma de trabajar: crear la figura y sus gráficas con \texttt{plt.subplots} y guardarlas en variables, y después llamar a los métodos de cada gráfica. La figura \ref{fig:plot_text} se puede hacer también así:
\switchcolumn
\subsection{Two ways of working: pyplot and objects}\label{sec:ax_interface-2}\index[eng]{Matplotlib!object-oriented interface}
So far we have used \texttt{pyplot} functions, which act on the current figure and graph. Matplotlib has a second way of working: create the figure and its graphs with \texttt{plt.subplots} and store them in variables, and then call the methods of each graph. Figure \ref{fig:plot_text} can also be made this way:
\end{paracol}
\begin{minted}{python}
fig, ax = plt.subplots()
ax.plot(t, y)
ax.set_title("Evolución de un sistema amortiguado")
ax.set_xlabel('t (s)')
ax.set_ylabel('x (m)')
ax.text(2.5, 0.8, r'$x=e^{-t}\cos(2\pi t)$')
\end{minted}

\begin{paracol}{2}
\texttt{fig} es la figura y \texttt{ax}, el área de dibujo (el objeto \texttt{Axes}). Con \texttt{fig, axs = plt.subplots(2, 1)} se crean dos gráficas, \texttt{axs[0]} y \texttt{axs[1]}, y queda claro en cuál dibuja cada instrucción. Por eso esta forma es la recomendada cuando hay varias gráficas o cuando se dibuja dentro de una función. Para una gráfica rápida, \texttt{pyplot} es más cómodo. La mayoría de las funciones tienen el mismo nombre en las dos formas (\texttt{plot}, \texttt{scatter}, \texttt{hist}, \texttt{legend}, \texttt{grid}, \texttt{text}…), pero las que \emph{cambian} una propiedad de la gráfica llevan delante \texttt{set\_} cuando son métodos (tabla \ref{tab:pyplot_ax}).

\textbf{No las mezcles sin darte cuenta.} \texttt{ax.xlabel(\textquotesingle{}t\textquotesingle{})} da un \texttt{AttributeError} (los objetos \texttt{Axes} no tienen \texttt{xlabel}, sino \texttt{set\_xlabel}), y \texttt{plt.set\_xlabel(\textquotesingle{}t\textquotesingle{})} también. Es uno de los errores más frecuentes del código que proponen los asistentes de IA, que mezclan ejemplos escritos de las dos formas.
\switchcolumn
\texttt{fig} is the figure and \texttt{ax} the plotting area (the \texttt{Axes} object). With \texttt{fig, axs = plt.subplots(2, 1)} we create two graphs, \texttt{axs[0]} and \texttt{axs[1]}, and it is clear on which one each instruction draws. \subsection{Ejes no lineales}\index{Matplotlib!escala logarítmica}
Las funciones \texttt{xscale} e \texttt{yscale} cambian la escala de los ejes. Reciben como argumento el tipo de escala:
    \begin{itemize}
        \item \texttt{\textquotesingle{}linear\textquotesingle{}}: escala lineal (la que se usa por defecto).
        \item \texttt{\textquotesingle{}log\textquotesingle{}}: escala logarítmica. Solo admite valores positivos; los demás no se dibujan, sin ningún aviso.
        \item \texttt{\textquotesingle{}symlog\textquotesingle{}}: escala logarítmica para valores positivos y negativos. Como el logaritmo tiende a $-\infty$ cuando su argumento se acerca a cero, en una zona alrededor del cero la escala es lineal.
        \item \texttt{\textquotesingle{}logit\textquotesingle{}}: para valores $p$ entre $0$ y $1$ (por ejemplo, probabilidades). Representa $\log\frac{p}{1-p}$, que amplía las zonas próximas a $0$ y a $1$.
    \end{itemize}
También se puede definir una escala propia mediante una función.

En el siguiente ejemplo se usan \texttt{xscale} e \texttt{yscale} para generar la figura \ref{fig:scale}.         \item \texttt{\textquotesingle{}symlog\textquotesingle{}}: logarithmic scale for positive and negative values. As the logarithm tends to $-\infty$ when its argument approaches zero, the scale is linear in a region around zero.

\begin{paracol}{2}
\paragraph{Rectas en escala logarítmica.} La escala logarítmica no sirve solo para que quepan datos muy grandes y muy pequeños. Su uso más importante es reconocer leyes:
\begin{itemize}
\item Si $y=Ce^{ax}$, entonces $\log y=\log C+a\,x\log e$: en escala semilogarítmica (solo el eje $y$ logarítmico) la gráfica es una \emph{recta}. Es lo que ocurre en la segunda gráfica de la figura \ref{fig:scale}.
\item Si $y=Cx^{p}$, entonces $\log y=\log C+p\log x$: en escala log-log (los dos ejes logarítmicos) la gráfica es una recta \emph{cuya pendiente es el exponente} $p$.
\end{itemize}
La exponencial no es una recta en escala log-log (tercera gráfica). Las funciones \texttt{semilogy}, \texttt{semilogx} y \texttt{loglog} dibujan directamente con esas escalas. En la sección \ref{sec:graf_verif} usaremos la gráfica log-log para medir cómo disminuye el error de un método numérico.

Fíjate también en que $x=0$ está en los datos, pero no aparece en la tercera gráfica: $\log 0$ no existe y Matplotlib descarta ese punto sin avisar.
\switchcolumn
\paragraph{Straight lines on a logarithmic scale.} The logarithmic scale is not only useful to fit very large and very small data in the same graph. Its most important use is to recognize laws:
\begin{itemize}
\item If $y=Ce^{ax}$, then $\log y=\log C+a\,x\log e$: on a semi-logarithmic scale (only the $y$-axis logarithmic) the graph is a \emph{straight line}. This is what happens in the second graph of figure \ref{fig:scale}.
\item If $y=Cx^{p}$, then $\log y=\log C+p\log x$: on a log-log scale (both axes logarithmic) the graph is a straight line \emph{whose slope is the exponent} $p$.
\end{itemize}
The exponential is not a straight line on a log-log scale (third graph). The functions \texttt{semilogy}, \texttt{semilogx} and \texttt{loglog} plot directly with those scales. In section \ref{sec:graf_verif} we will use the log-log graph to measure how the error of a numerical method decreases.

Notice also that $x=0$ is in the data but does not appear in the third graph: $\log 0$ does not exist, and Matplotlib discards that point without warning.
\end{paracol}

en la región del plano $x\in[-1.5,1.5]$, $y\in[-2,2]$.

\begin{equation*}

\end{equation*}
in the region of the plane $x\in[-1.5,1.5]$, $y\in[-2,2]$.

\begin{paracol}{2}
Ahora la región no es cuadrada, y los puntos no están igual de espaciados en los dos ejes. Es decir, el elemento \texttt{Zm[i, j]} corresponde al punto \texttt{(x[j], y[i])}, y no al \texttt{(x[i], y[j])}. \switchcolumn
Now the region is not square, and the points are not equally spaced on the two axes. The coordinate matrices are not square either: \texttt{Xm.shape} is \texttt{(50, 25)}. \textbf{Watch the order}: \texttt{meshgrid(x, y)} produces matrices with as many \emph{rows} as elements in \texttt{y} and as many \emph{columns} as elements in \texttt{x}. That is, the element \texttt{Zm[i, j]} corresponds to the point \texttt{(x[j], y[i])}, not to \texttt{(x[i], y[j])}. \section{Animaciones}\index{Matplotlib!animaciones}
Matplotlib también permite crear animaciones con el módulo \texttt{matplotlib.animation}. Una animación es una secuencia de fotogramas, y cada fotograma es una figura. La forma más directa de crearla tiene tres pasos:
\begin{enumerate}
    \item Crear el objeto que va a escribir el fichero de la animación (el \emph{writer}).
    \item Dibujar el fondo: lo que no cambia de un fotograma a otro.
    \item En un bucle, cambiar lo que se mueve y capturar cada fotograma.
\end{enumerate}
Como ejemplo, haremos que un círculo rojo recorra la gráfica de la función seno.

\paragraph{Crear el writer.} \texttt{PillowWriter} guarda la animación como un GIF, que se puede ver en cualquier navegador. Con \texttt{fps} indicamos el número de fotogramas por segundo:
\switchcolumn
\section{Animations}\index[eng]{Matplotlib!animations}
Matplotlib can also create animations with the module \texttt{matplotlib.animation}. An animation is a sequence of frames, and each frame is a figure. The most direct way to create one has three steps:
\begin{enumerate}
    \item Create the object that will write the animation file (the \emph{writer}).
    \item Draw the background: what does not change from one frame to the next.
    \item In a loop, change what moves and capture each frame.
\end{enumerate}
As an example, we will make a red circle travel along the graph of the sine function.

\paragraph{Create the writer.} \texttt{PillowWriter} saves the animation as a GIF, which can be viewed in any browser. With \texttt{fps} we set the number of frames per second:
\end{paracol}
\begin{minted}{python}
import numpy as np
import matplotlib.pyplot as plt
from matplotlib.animation import PillowWriter

writer = PillowWriter(fps=20)
\end{minted}
\begin{paracol}{2}
\paragraph{Dibujar el fondo.} Creamos la figura y dibujamos lo que va a permanecer constante durante la animación: la curva del seno y las etiquetas de los ejes. También creamos el círculo rojo, pero sin coordenadas (dos listas vacías), porque se las daremos en cada fotograma. Guardamos en la variable \texttt{punto} el objeto que devuelve \texttt{plot} para poder modificarlo después. La coma de \texttt{punto,} es necesaria porque \texttt{plot} devuelve una lista de líneas, y aquí solo hay una.
\switchcolumn
\paragraph{Draw the background.} We create the figure and draw what will remain constant during the animation: the sine curve and the axis labels. We also create the red circle, but without coordinates (two empty lists), because we will give them to it in each frame. We store the object returned by \texttt{plot} in the variable \texttt{punto} so that we can modify it later. The comma in \texttt{punto,} is needed because \texttt{plot} returns a list of lines, and here there is only one.
\end{paracol}
\begin{minted}{python}
fig = plt.figure()
n = 200
x = np.linspace(0, 6*np.pi, n)
y = np.sin(x)
plt.plot(x, y, 'b')
punto, = plt.plot([], [], 'ro', markersize=10)
plt.xlabel('x')
plt.ylabel('sen(x)')
\end{minted}
\begin{paracol}{2}
\paragraph{Cambiar lo que se mueve y capturar los fotogramas.} Todo ocurre dentro del bloque \texttt{with writer.saving(...)}, al que le indicamos la figura, el nombre del fichero y la resolución en puntos por pulgada (\texttt{dpi}). En cada iteración del bucle se cambia la posición del círculo con \texttt{set\_data}, que espera dos secuencias (por eso los corchetes, aunque sea un solo punto), y \texttt{grab\_frame} añade la figura tal como está en ese momento como un fotograma más.
\switchcolumn
\paragraph{Change what moves and capture the frames.} Everything happens inside the block \texttt{with writer.saving(...)}, to which we give the figure, the file name and the resolution in dots per inch (\texttt{dpi}). In each iteration of the loop, the position of the circle is changed with \texttt{set\_data}, which expects two sequences (hence the square brackets, even for a single point), and \texttt{grab\_frame} adds the figure, as it is at that moment, as one more frame.
\end{paracol}
\begin{minted}{python}
with writer.saving(fig, 'seno.gif', dpi=100):
    for i in range(n):
        punto.set_data([x[i]], [y[i]])
        writer.grab_frame()
\end{minted}

To get an \texttt{.mp4} video instead of a GIF, use \texttt{FFMpegWriter} instead of \texttt{PillowWriter}, but it needs the program \texttt{ffmpeg} to be installed (in Anaconda, with \texttt{conda install ffmpeg}). \begin{paracol}{2}
\section[Gráficas para verificar un resultado]{Gráficas para verificar un resultado\sectionmark{Gráficas para verificar \textreferencemark\ Graphs to verify}}\label{sec:graf_verif}\index{Verificación!con gráficas}
En el capítulo \ref{ch:intpr} (sección \ref{sec:verif}) vimos que un programa que se ejecuta sin errores no es necesariamente un programa correcto, y algunas estrategias para comprobarlo. Las gráficas son una de las herramientas más potentes para ello: en los capítulos siguientes, casi siempre que calculemos algo lo comprobaremos dibujándolo.

\paragraph{Una gráfica que se pueda defender.} Una gráfica que acompaña a un resultado tiene que poder entenderla otra persona sin preguntarnos nada. Antes de darla por buena, comprueba que:
\begin{itemize}
\item Los ejes indican la magnitud y sus unidades.
\item Si hay más de una curva, hay una leyenda.
\item Los datos medidos o calculados en puntos sueltos se dibujan con marcadores. Las líneas continuas son para funciones o para guiar la vista.
\item La escala es la adecuada: si los datos abarcan varios órdenes de magnitud, logarítmica.
\item Los mapas de color tienen su barra de color.
\item Para comparar dos curvas casi iguales (por ejemplo, un resultado numérico y la solución exacta), no basta con dibujarlas superpuestas: dos curvas que difieren en un $1\%$ parecen idénticas. Hay que dibujar su diferencia.
\end{itemize}

\paragraph{Medir el orden de un error.} Muchos métodos numéricos dependen de un parámetro $h$ (un paso, una distancia entre puntos) y su error se comporta como $E\approx Ch^p$: el método es \emph{de orden} $p$. Como vimos al hablar de las escalas logarítmicas, en una gráfica log-log esa ley es una recta de pendiente $p$. Por ejemplo, la derivada de una función puede aproximarse por
$$f'(x)\approx\frac{f(x+h)-f(x)}{h}.$$
El código siguiente calcula el error de esta aproximación para $f(x)=\sin x$ en $x=1$, cuya derivada exacta conocemos, $\cos 1$, con $h=10^{-1}, 10^{-2},\ldots,10^{-15}$. El resultado está en la figura \ref{fig:error_h}.
\switchcolumn
\section[Graphs to verify a result]{Graphs to verify a result\sectionmark{Gráficas para verificar \textreferencemark\ Graphs to verify}}\label{sec:graf_verif-2}\index[eng]{Verification!with graphs}
In chapter \ref{ch:intpr} (section \ref{sec:verif}) we saw that a program that runs without errors is not necessarily a correct program, and some strategies to check it. Graphs are one of the most powerful tools for this: in the following chapters, almost every time we compute something we will check it by plotting it.

\paragraph{A graph you can defend.} A graph that accompanies a result must be understandable by someone else without asking us anything. Before accepting it, check that:
\begin{itemize}
\item The axes show the quantity and its units.
\item If there is more than one curve, there is a legend.
\item Data measured or computed at individual points are drawn with markers. Continuous lines are for functions or to guide the eye.
\item The scale is appropriate: logarithmic, if the data span several orders of magnitude.
\item Color maps have their color bar.
\item To compare two almost identical curves (for example, a numerical result and the exact solution), it is not enough to draw them on top of each other: two curves that differ by $1\%$ look identical. Their difference must be plotted.
\end{itemize}

\paragraph{Measuring the order of an error.} Many numerical methods depend on a parameter $h$ (a step, a distance between points), and their error behaves as $E\approx Ch^p$: the method is \emph{of order} $p$. As we saw when discussing logarithmic scales, on a log-log graph this law is a straight line with slope $p$. For example, the derivative of a function can be approximated by
$$f'(x)\approx\frac{f(x+h)-f(x)}{h}.$$
The following code calculates the error of this approximation for $f(x)=\sin x$ at $x=1$, whose exact derivative we know, $\cos 1$, with $h=10^{-1}, 10^{-2},\ldots,10^{-15}$. The result is in figure \ref{fig:error_h}.
\end{paracol}
\begin{minted}{python}
import numpy as np
import matplotlib.pyplot as plt

h = np.logspace(-1, -15, 15)    # 1e-1, 1e-2, ..., 1e-15
aprox = (np.sin(1 + h) - np.sin(1)) / h
error = np.abs(aprox - np.cos(1))

fig, ax = plt.subplots()
ax.loglog(h, error, 'o-', label='diferencia hacia delante')
ax.loglog(h, h, 'k--', label='pendiente 1 (referencia)')
ax.set_xlabel('h')
ax.set_ylabel('error absoluto')
ax.grid(True)
ax.legend()
\end{minted}
\begin{figure}[h]
    \centering
    \includegraphics[width=0.7\linewidth]{figuras/plt_error_h.png}
    \bicaption{Error de la aproximación de $f'(1)$ por diferencias hacia delante para $f(x)=\sin x$, en función del paso $h$}{Error of the forward difference approximation of $f'(1)$ for $f(x)=\sin x$, as a function of the step $h$}
    \label{fig:error_h}
\end{figure}
\begin{paracol}{2}
Para $h$ entre $10^{-1}$ y $10^{-7}$ los puntos están sobre una recta paralela a la de referencia: el error es proporcional a $h$ y el método es de orden $1$. La pendiente puede medirse con dos puntos de la recta:
\begin{minted}{python}
In [1]: (np.log10(error[3]) - np.log10(error[0])) / (np.log10(h[3]) - np.log10(h[0]))
Out[1]: 1.002942988564625
\end{minted}
Para $h$ menores que $10^{-8}$, el error \emph{aumenta} al disminuir $h$. No es un fallo del programa: es el error de redondeo, que estudiaremos en el capítulo \ref{chp:arit}. Sin la gráfica en escala log-log, nada de esto se vería.

\paragraph{Una gráfica no es una prueba.} Una gráfica que parece razonable puede ocultar un error. En el ejercicio \ref{ej:precip} se corrigen los datos de un fichero de precipitaciones, y la gráfica de los datos corregidos se parece mucho a la de los datos originales tanto si la corrección está bien hecha como si no. La gráfica orienta; las comprobaciones numéricas (\texttt{assert}, \texttt{np.allclose}…) confirman.
\switchcolumn
For $h$ between $10^{-1}$ and $10^{-7}$ the points lie on a straight line parallel to the reference line: the error is proportional to $h$, and the method is of order $1$. The slope can be measured with two points on the line:
\begin{minted}{python}
In [1]: (np.log10(error[3]) - np.log10(error[0])) / (np.log10(h[3]) - np.log10(h[0]))
Out[1]: 1.002942988564625
\end{minted}
For $h$ smaller than $10^{-8}$, the error \emph{increases} as $h$ decreases. This is not a bug in the program: it is the rounding error, which we will study in chapter \ref{chp:arit}. Without the log-log graph, none of this would be visible.

\paragraph{A graph is not a proof.} A graph that looks reasonable may hide an error. In exercise \ref{ej:precip-en}, the data in a precipitation file are corrected, and the graph of the corrected data looks very much like that of the original data, whether the correction is right or not. The graph guides; numerical checks (\texttt{assert}, \texttt{np.allclose}…) confirm.
\end{paracol}
