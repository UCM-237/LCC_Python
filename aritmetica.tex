\section{Binary and decimal representations}\index[eng]{Binary}

Real numbers can be represented on a line extending from $-\infty$ to $+\infty$. Most of them do not have an exact numerical representation, because they have infinitely many decimal digits.

The integers $1, -1, 2, -2, 3, -3, \cdots$ have an exact numerical representation. \index[eng]{Scientific notation} However, when an integer has many digits, we usually approximate it and write it in scientific notation, multiplying it by a power of $10$. Let's take an example from chemistry: the number of entities (atoms, molecules\ldots) in a mole of a substance is Avogadro's number, $N_A = 6.02214076 \times 10^{23}$. This number of entities is a 24-digit integer, but we write it using just 9 of its digits (sometimes only the first three are given).

\index[eng]{Truncation} When we truncate a number, that is, when we drop all its digits to the right of a given one, we are approximating it by a rational number, i.e., a number that can be written as the quotient of two integers: $1/2, 3/4, \cdots$

In this last case, the representation does not terminate, but it is periodic: after the first zero following the point, the sequence $0011$ repeats endlessly. Rational numbers always have either a finite or a periodic infinite representation.

The rational number $1/3=(0.333\cdots)_{10} = (0.010101\cdots)_2$ has only periodic infinite representations, both in base 10 and in base 2. However, it has a finite representation in base 3: $1/3=(0.1)_{3}= 0 \times 3^0 + 1\times 3^{-1}$.

This is a first source of error that we must take into account when we use a computer for scientific computing. As we will see throughout the chapter, it is not the only one.

\paragraph{Positive integers.} The simplest way to represent numbers would be to use the memory registers directly to store them in binary. If we consider a computer with 16-bit registers, we could store in them the numbers between $0$ and $2^{16}-1=65535$. This last number would be represented by a 1 in every position of the register, 16 ones in total. It is the largest integer we can represent with a 16-bit register:

Este sistema de representación solo admite números enteros no negativos. El menor número que podemos representar es el cero, y el mayor ---que dependerá del tamaño $n$ de los registros del ordenador--- es $2^n-1$. Es evidente que este sistema de representación resulta insuficiente.

\paragraph{Enteros positivos y negativos.}
Una primera mejora consistiría en ampliar el sistema de representación para que admita también números negativos. Una posibilidad sería reservar uno de los bits del registro para representar el signo \index{Bit de signo}, y usar los restantes para representar el valor absoluto del número. En nuestro ejemplo de un registro de 16 bits, el número más grande sería ahora $2^{15}-1$ y el más pequeño $-2^{15}+1$. El cero tendría una doble representación, una con signo más y otra con signo menos.

Una representación alternativa, la que usan prácticamente todos los ordenadores actuales, es la conocida como \emph{complemento a 2} \index{Complemento a dos} \index{Representación numérica!complemento a dos}. Supongamos un registro de $n$ bits:
\begin{itemize}
\item Un entero $x$ no negativo se almacena empleando directamente su representación binaria. El intervalo de enteros no negativos representables es $0 \le x \le 2^{n-1}-1$.
\item Un entero negativo $-x$, donde $1 \le x \le 2^{n-1}$, se almacena como la representación binaria del entero positivo $2^{n}-x$.
\item El número así construido recibe el nombre de complemento a 2 de $x$.
\end{itemize}
En general, dado un número entero $N<2^n$, su complemento a dos en una representación binaria de $n$ dígitos se define como:
\begin{equation*}
C_2^N=2^n-N
\end{equation*}
En la tabla \ref{tabla:c2} se muestra un ejemplo de esta representación para un registro de 4 bits.
\switchcolumn
This representation system only accepts non-negative integers. The smallest number we can represent is zero, and the largest one ---which depends on the size $n$ of the computer registers--- is $2^n-1$. Clearly, this representation system is insufficient.

\paragraph{Positive and negative integers.} A first improvement would be to extend the system so that it also admits negative numbers. One option would be to reserve one bit of the register to represent the sign\index[eng]{Sign bit}, and use the remaining bits to represent the absolute value of the number. In our example of a 16-bit register, the largest number would now be $2^{15}-1$ and the smallest $-2^{15}+1$. Zero would have two representations, one with a plus sign and another with a minus sign.

An alternative representation, the one used by virtually all current computers, is known as \emph{two's complement}.\index[eng]{Two's complement} \index[eng]{Number representation!two's complement} Consider an $n$-bit register:
\begin{itemize}
    \item A non-negative integer $x$ is stored directly using its binary representation. The range of representable non-negative integers is $0 \le x \le 2^{n-1}-1$.
    \item A negative integer $-x$, where $1 \le x \le 2^{n-1}$, is stored as the binary representation of the positive integer $2^{n}-x$.
    \item The number built in this way is called the two's complement of $x$.
\end{itemize}
In general, given an integer $N<2^n$, its two's complement in an $n$-digit binary representation is defined as:
\begin{equation*}
 C_2^N=2^n-N
\end{equation*}

The two's complement representation has the following properties:
\begin{itemize}
    \item The representation of positive numbers coincides with their binary value.
    \item The number zero has a single representation.
    \item The range of representable values with $n$ bits is $-2^{n-1} \le x \le  2^{n-1}-1$.
    \item The value of a negative number is obtained by computing the two's complement of the binary number that represents it and changing its sign.
\end{itemize}
A practical way to compute the two's complement of a binary number is to copy the number from right to left until the first 1 appears. Once the first 1 has been copied, the remaining bits are \emph{complemented} (each 0 becomes a 1 and each 1 becomes a 0). For instance, the two's complement of the number 2 (0010 in a 4-bit representation) is 1110:

El bit distinto de cero no puede almacenarse en un registro de cuatro bits: se dice que el resultado de la operación \emph{desborda} el tamaño del registro. Ese bit se descarta, con lo que el resultado es cero, como corresponde a la suma $2+(-2)$. Esta es la motivación fundamental para emplear la representación en complemento a dos: no hacen falta circuitos especiales para restar, ya que la diferencia se calcula como la suma del minuendo y el complemento a dos del sustraendo.

Esta misma propiedad tiene una consecuencia peligrosa: si el resultado de una operación entre enteros no cabe en el registro, el bit sobrante se descarta igualmente y se obtiene un número completamente distinto, \emph{sin ningún aviso}. Por ejemplo, con 4 bits, $7+1=0111+0001=1000$, que representa a $-8$. Lo veremos en Python en la sección \ref{sec:arit_python}.

\subsection{Números no enteros: representación en punto fijo y en punto flotante}
La representación de números no enteros se emplea para representar de modo aproximado los números reales. Como hemos dicho antes, los números racionales periódicos y los números irracionales no pueden representarse de forma exacta mediante un número finito de cifras. Por esta razón, su representación es siempre aproximada. Para los números racionales no periódicos, la representación será exacta o aproximada dependiendo del número de que se trate, del tamaño de los registros del ordenador y del sistema empleado para la representación. Los dos sistemas de representación más conocidos son la representación en punto fijo y, de especial interés para el cálculo científico, la representación en punto flotante.

\paragraph*{Representación en punto fijo.} \index{Representación numérica!en punto fijo}En la representación en punto fijo, el registro empleado para almacenar un número se divide en tres partes:
\begin{itemize}
\item 1 bit para almacenar el signo del número.
\item Un campo de bits de tamaño fijo para representar la parte entera del número.
\item Un campo de bits de tamaño fijo para representar la parte fraccionaria del número.
\end{itemize}

Por ejemplo, si tenemos un registro de 16 bits podemos reservar 1 bit para el signo, 7 para la parte entera y 8 para la parte fraccionaria. La representación en punto fijo del número binario $-10111.0011101101$ sería:
\switchcolumn
The result of the addition is a number whose last four bits are 0. The non-zero bit cannot be stored in a 4-bit register: we say that the result of the operation \emph{overflows} the register size. That bit is discarded, so the result is zero, as expected from the addition $2+(-2)$. This is the main motivation for the two's complement representation: no special circuits are needed to subtract, because the difference is computed as the sum of the minuend and the two's complement of the subtrahend.

This same property has a dangerous consequence: if the result of an integer operation does not fit in the register, the extra bit is discarded anyway and a completely different number is obtained, \emph{without any warning}. For instance, with 4 bits, $7+1=0111+0001=1000$, which represents $-8$. We will see it in Python in section \ref{sec:arit_python-2}.

\subsection{Non-integer numbers: fixed-point and floating-point representations}
Non-integer representations are used to represent real numbers approximately. As we said before, periodic rational numbers and irrational numbers cannot be represented exactly with a finite number of digits. This is why their representation is always an approximation. For non-periodic rational numbers, the representation will be exact or approximate depending on the number itself, the size of the computer registers and the representation system. The two best-known representation systems are fixed-point representation and, of special interest for scientific computing, floating-point representation.

    \item A fixed-size field of bits to represent the fractional part of the number.

Veamos en detalle el estándar IEEE 754.

\paragraph*{El estándar IEEE 754.}\index{Estándar IEEE 754}
El estándar se estableció pensando en dos tamaños de registro. El primero emplea 32 bits para guardar los números en punto flotante y recibe el nombre de formato de precisión simple. El segundo emplea 64 bits y se conoce como formato de precisión doble. Es el que usa Python para sus números reales (el tipo \texttt{float}).

\subparagraph*{Precisión simple.}\index{Estándar IEEE 754!precisión simple} Empecemos por describir el formato de precisión simple. Se reserva un bit para el signo: si el bit vale 1, se trata de un número negativo, y si vale 0, de un número positivo. De los 31 bits restantes, 8 se emplean para representar el exponente y 23 para representar la mantisa. En el registro, los bits se guardan en ese orden: signo, exponente, mantisa.

\index{Mantisa!normalizada}Si analizamos cómo es la mantisa de un número binario en punto flotante, nos damos cuenta de que su parte entera siempre vale 1 (el único dígito distinto de cero en binario). Por tanto, podemos guardar en la mantisa solo la parte del número que está a la derecha del punto y considerar que el 1 de la parte entera está implícito. Por ejemplo, del número binario $1.010111\times 2^{3}$ solo guardaríamos la cifra $010111$. Sabemos que el 1 de la parte entera está ahí, pero no lo representamos. A este tipo de mantisa la llamaremos normalizada; más adelante veremos por qué.

\index{Exponente!representación en exceso} En cuanto al exponente, es preciso buscar una forma de representar exponentes positivos y negativos. El estándar establece para ello lo que se llama la representación \emph{en exceso}. Con ocho bits podemos representar $2^8=256$ números distintos, desde el $[00000000]=0$ hasta el $[11111111]=255$.

Si partimos nuestra colección de números en dos, podemos emplear la primera mitad para representar los exponentes negativos, reservando el mayor de ellos para representar el cero, y la segunda para representar los exponentes positivos. Para obtener el valor del exponente basta restar al contenido del campo de exponente el número reservado para representar el cero. Se dice entonces que la representación se realiza \emph{en exceso} a dicho número.

En el formato de precisión simple, la primera mitad de los números disponibles va del 0 al 127 y la segunda mitad del 128 al 255. La representación se realiza entonces en exceso a 127. La tabla \ref{tabex} muestra unos cuantos ejemplos de la representación \emph{en exceso}.

Although this representation works for the represented number, it is clear that we cannot represent in this way a number with a negative exponent, such as $1.011101\times 2^{-3}$. Furthermore, we have divided the 16-bit register arbitrarily; we could have chosen a different allocation of bits between mantissa and exponent. In fact, until the mid-1980s, each computer manufacturer adopted its own floating-point representation. As a consequence, the same programs, run on different computers, gave different results.

In 1976, John Palmer, from the Intel company, who was preparing the 8087 maths coprocessor, hired William Kahan, a professor at the University of California, Berkeley, as a consultant to design its arithmetic. The following year, the IEEE set up a committee to draw up a common standard, that is, a floating-point representation that all manufacturers would adopt. The proposal that finally prevailed was the one by Kahan, Jerome Coonen and Harold Stone (the K-C-S document), based on the design of the 8087. The standardisation process was slow: the standard, known as IEEE 754, was not approved until 1985, and it was revised in 2008 and 2019. Kahan received the Turing Award in 1989 for this work. IEEE stands for \emph{Institute of Electrical and Electronics Engineers}, an international professional association that, among other things, establishes industrial standards in the fields of electricity, electronics and computing. Let's look at the IEEE 754 standard in some detail.

\paragraph{The IEEE 754 standard.}\index[eng]{IEEE 754 standard} The standard was designed for two register sizes. The first one uses 32 bits to store floating-point numbers and is known as the single precision format. The second one uses 64 bits and is known as the double precision format. It is the one Python uses for its real numbers (the \texttt{float} type).

\subparagraph{Single precision.}\index[eng]{IEEE 754 standard!single precision} Let's start by describing the single precision format. One bit is reserved for the sign: if the bit is 1, the number is negative, and if it is 0, the number is positive. Of the remaining 31 bits, 8 are used to represent the exponent and 23 to represent the mantissa. In the register, the bits are stored in this order: sign, exponent, mantissa.

\index[eng]{Mantissa!normalised} If we examine the mantissa of a binary floating-point number, we realise that its integer part is always 1 (the only non-zero digit in binary). Therefore, we only need to store the digits to the right of the point, and we can consider the leading 1 of the integer part implicit. For instance, for the binary number $1.010111\times 2^{3}$ we only store the figure $010111$. We know the leading $1$ of the integer part is there, but we do not represent it. We will call this kind of mantissa a normalised mantissa; we shall see why later on.

\index[eng]{Exponent!biased} We need a way to represent positive and negative exponents. For this, the standard prescribes what is known as a \emph{biased} representation. Using 8 bits, we can represent $2^8 = 256$ different numbers, from $[00000000] = 0$ to $[11111111] = 255$.

If we split this collection of numbers into two halves, we can use the lower half to represent negative exponents, using the largest number of this half to represent zero, and the upper half to represent positive exponents. To obtain the value of the exponent, it is enough to subtract the number reserved to represent zero from the content of the exponent field. We then say that the representation is \emph{biased} by that number.

In the single precision format, the first half of the available numbers ranges from 0 to 127 and the second half from 128 to 255. The representation is then biased by 127. Table \ref{tabex} shows some examples of this \emph{biased} representation.

What is the largest number we could represent in single precision? In principle, we might think that it is the one with all its mantissa bits set to one (the largest possible mantissa) and all its exponent bits also set to one (the largest possible exponent). \section{Errores en la representación numérica}\label{errn}
\sectionmark{Errores de representación \textreferencemark\ Num. rep. errors}
Como hemos visto, cualquier representación numérica que empleemos en el ordenador está sometida a errores derivados del tamaño finito de los registros. Vamos a centrarnos en el estudio de los errores cometidos al representar números en el formato de punto flotante del estándar IEEE 754.

En primer lugar, solo hay una cantidad finita de números que admiten una representación exacta: los que se obtienen directamente de los valores ---unos y ceros--- contenidos en un registro, interpretados de acuerdo con las especificaciones del estándar. Estos números reciben el nombre de números máquina.

Un número real no será un número máquina si, \index{Número máquina}

\begin{enumerate}
\item Una vez escrito en formato de punto flotante, su exponente está fuera del rango admitido para los exponentes: es demasiado grande o demasiado pequeño.

\item Una vez escrito en formato de punto flotante, su mantisa contiene más dígitos de los que caben en la mantisa del formato.
\end{enumerate}

Si el exponente se sale del rango admitido, se produce un error de desbordamiento. Si el valor es demasiado grande, el desbordamiento se produce por exceso (\emph{overflow}), y el ordenador asignará al número el valor $\pm \infty$. Si el valor es demasiado pequeño (más próximo a cero que el menor número desnormalizado), el desbordamiento se produce por defecto (\emph{underflow}), y el ordenador asignará al número el valor cero.

Si la mantisa del número tiene más dígitos de los que caben, hay que recortarla para que el número sea representable. Es decir, se sustituye el número por un número máquina cercano. Este proceso se conoce como redondeo, y el error cometido, como error de redondeo.

\subsection{Error de redondeo unitario} \index{Error de redondeo}
Supongamos que tenemos un número no máquina $x=(1.a_1a_2\cdots a_{23}a_{24}\cdots)\times2^{\text{exp}}$.

\paragraph{Aproximación por truncamiento.} \index{Truncamiento}Si queremos representarlo en precisión simple, solo podremos guardar 23 bits de su mantisa. Una solución es truncar el número, eliminando directamente todos los bits de la mantisa a partir del 24: $x\approx x_T= (1.a_1a_2\cdots a_{23})\times2^{\text{exp}}$. Como hemos eliminado algunos bits, el número máquina $x_T$ por el que hemos aproximado nuestro número es menor que él.

\paragraph{Aproximación por exceso.} \index{Aproximación por exceso} Otra opción sería aproximarlo por el número máquina inmediatamente superior. Esto equivale a eliminar todos los bits de la mantisa a partir del 24 y sumar 1 en la posición 23 de la mantisa: $x\approx x_E=  (1.a_1a_2\cdots a_{23}+2^{-23})\times2^{\text{exp}}$. En este caso, aproximamos por un número máquina mayor que el número aproximado.

\paragraph{Redondeo.} Cualquier número real dentro del rango representable estará comprendido entre dos números máquina: $x_T\leq x\leq x_E$.

El estándar IEEE 754 aproxima, por defecto, cada número real por el número máquina más cercano, sea $x_T$ o $x_E$. Si el número está exactamente a mitad de camino entre los dos, se elige el que termina en 0 (redondeo \emph{al par}), para que los redondeos no se desvíen sistemáticamente hacia arriba ni hacia abajo.

\section{Errors in numerical representation}
\sectionmark{Errores de representación \textreferencemark\ Num. rep. errors}
As we have seen, any numerical representation we use in a computer is subject to errors due to the finite size of the registers. We are going to focus on the errors made when representing numbers in the floating-point format of the IEEE 754 standard.

First, there is only a finite set of numbers with an exact representation: those obtained directly from the values ---ones and zeros--- contained in a register, interpreted according to the specifications of the standard. These numbers are called machine numbers.\index[eng]{Machine number}

A real number will not be a machine number if,
\begin{enumerate}
	\item Once written in floating-point format, its exponent is out of the range admitted for exponents: it is too large or too small.
	\item Once written in floating-point format, its mantissa has more digits than fit in the mantissa of the format.
\end{enumerate}
If the exponent is out of the admitted range, an overflow or underflow occurs. If the value is too large, we get an \emph{overflow}, and the computer will assign the number the value $\pm \infty$. If the value is too small (closer to zero than the smallest denormalised number), we get an \emph{underflow}, and the computer will assign the number the value zero.

If the mantissa of the number has more digits than fit, it must be cut so that the number becomes representable. In other words, we replace the number with a nearby machine number. This process is known as rounding, and the error made, as rounding error.

\subsection{Unit round-off error}\index[eng]{Rounding error}
Suppose we have a non-machine number $x=(1.a_1a_2\cdots a_{23}a_{24}\cdots)\times2^{\text{exp}}$.

\paragraph{Approximation by truncation.}\index[eng]{Truncation} If we want to represent it in single precision, we can only store 23 bits of its mantissa. A possible solution is to truncate the number, eliminating all mantissa bits from the 24th on: $x\approx x_T=  (1.a_1a_2\cdots a_{23})\times2^{\text{exp}}$. Because we have eliminated some bits, the machine number $x_T$ we have taken to approximate our number is smaller than it.

\paragraph{Approximation by excess.} Another option is to approximate it by the next machine number above. This is the same as eliminating all mantissa bits from the 24th on and adding 1 in position 23 of the mantissa: $x\approx x_E=  (1.a_1a_2\cdots a_{23}+2^{-23})\times2^{\text{exp}}$. In this case, we approximate by a machine number larger than the approximated number.

\paragraph{Rounding.} Any real number inside the representable range lies between two machine numbers: $x_T\leq x\leq x_E$.

\section[Error de redondeo y error de truncamiento]{Error de redondeo y error de truncamiento\sectionmark{Redondeo y truncamiento \textreferencemark\ Rounding and truncation}}\label{sec:red_trunc}\index{Error de truncamiento}
En este capítulo hemos estudiado los errores que se deben a la aritmética del ordenador. Pero no son la única fuente de error de un cálculo científico. La mayoría de los métodos numéricos que veremos en los próximos capítulos sustituyen un problema matemático por otro aproximado: una derivada por un cociente de incrementos, una integral por una suma finita, una serie por unos cuantos términos. El error que se comete al hacerlo, aunque se calculara con aritmética exacta, se llama \emph{error de truncamiento} o \emph{error del método}. Además, los datos de partida suelen proceder de medidas y tienen su propia incertidumbre.

El error de truncamiento suele poder reducirse tanto como se quiera: basta tomar un paso más pequeño o más términos. El error de redondeo no. Y a menudo los dos tiran en sentidos opuestos. En la sección \ref{sec:graf_verif} del capítulo \ref{ch:matplotlib} aproximamos la derivada de $\sin x$ en $x=1$ con
$$f'(x)\approx\frac{f(x+h)-f(x)}{h},$$
y vimos en la figura \ref{fig:error_h} que el error disminuye al disminuir $h$ hasta $h\approx10^{-8}$, pero luego \emph{aumenta}. Ahora podemos explicarlo, e incluso predecirlo.

\begin{itemize}
\item \emph{Error de truncamiento.} Por el desarrollo de Taylor, $f(x+h)=f(x)+hf'(x)+\frac{h^2}{2}f''(\xi)$, con $\xi$ entre $x$ y $x+h$. Por tanto, el cociente difiere de $f'(x)$ en $\frac{h}{2}\vert f''(\xi)\vert$: es proporcional a $h$.
\item \emph{Error de redondeo.} $f(x+h)$ y $f(x)$ se calculan con un error relativo de hasta $\text{eps}/2$ cada uno. Al restarlas, como son casi iguales, sus dígitos más significativos se anulan y queda un error absoluto de hasta $\text{eps}\vert f(x)\vert$, que después se divide por $h$: es proporcional a $1/h$.
\end{itemize}
El error total es, aproximadamente,
\switchcolumn
\section[Rounding error and truncation error]{Rounding error and truncation error\sectionmark{Redondeo y truncamiento \textreferencemark\ Rounding and truncation}}\label{sec:red_trunc-2}\index[eng]{Truncation error}
In this chapter, we have studied the errors due to computer arithmetic. But they are not the only source of error in a scientific computation. Most of the numerical methods we will see in the following chapters replace a mathematical problem with an approximate one: a derivative with a difference quotient, an integral with a finite sum, a series with a few terms. The error made in doing so, even if the computation were done with exact arithmetic, is called \emph{truncation error} or \emph{method error}. In addition, input data often come from measurements and have their own uncertainty.

Truncation error can usually be made as small as we like: we just need to take a smaller step or more terms. Rounding error cannot. And they often pull in opposite directions. In section \ref{sec:graf_verif-2} of chapter \ref{ch:matplotlib} we approximated the derivative of $\sin x$ at $x=1$ with
$$f'(x)\approx\frac{f(x+h)-f(x)}{h},$$
and we saw in figure \ref{fig:error_h} that the error decreases as $h$ decreases down to $h\approx10^{-8}$, but then it \emph{increases}. Now we can explain it, and even predict it.

\begin{itemize}
\item \emph{Truncation error.} By Taylor's expansion, $f(x+h)=f(x)+hf'(x)+\frac{h^2}{2}f''(\xi)$, with $\xi$ between $x$ and $x+h$. Therefore, the quotient differs from $f'(x)$ by $\frac{h}{2}\vert f''(\xi)\vert$: it is proportional to $h$.
\item \emph{Rounding error.} $f(x+h)$ and $f(x)$ are each computed with a relative error of up to $\text{eps}/2$. When they are subtracted, since they are almost equal, their most significant digits cancel and an absolute error of up to $\text{eps}\vert f(x)\vert$ remains, which is then divided by $h$: it is proportional to $1/h$.
\end{itemize}
The total error is approximately,
\end{paracol}
\begin{equation*}
E(h)\approx \frac{h}{2}\vert f''(x)\vert+\frac{\text{eps}\,\vert f(x)\vert}{h}
\end{equation*}
\begin{paracol}{2}
El primer término domina para $h$ grandes y el segundo para $h$ pequeños. El mínimo se alcanza al anular la derivada de $E(h)$, en
$$h^*=\sqrt{\frac{2\,\text{eps}\,\vert f(x)\vert}{\vert f''(x)\vert}}.$$
Para $f(x)=\sin x$ en $x=1$, $\vert f(x)\vert=\vert f''(x)\vert$, y resulta $h^*=\sqrt{2\,\text{eps}}\approx 2\times10^{-8}$, con un error mínimo del orden de $10^{-8}$. Es justo lo que muestra la figura \ref{fig:error_h}. A la izquierda del mínimo, la gráfica sube con pendiente $-1$, como predice el término $\text{eps}\vert f(x)\vert/h$; los puntos se dispersan porque el error de redondeo depende de cómo se redondee cada número.

Las conclusiones son importantes, y nos acompañarán en el resto del curso:
\begin{itemize}
\item Un paso más pequeño no siempre da un resultado mejor. Con la diferencia hacia delante no se pueden obtener más de unas 8 cifras correctas de la derivada, por pequeño que se tome $h$.
\item Antes de ejecutar un cálculo, conviene \emph{predecir} cómo debería comportarse su error. Si el resultado no se comporta como se esperaba, hay un error en el programa o en la predicción, y en ambos casos hay algo que entender.
\item Para saber si un resultado es correcto hay que conocer los dos tipos de error: el del método, que depende del algoritmo, y el de redondeo, que depende de cómo se hacen las cuentas.
\end{itemize}
\switchcolumn
The first term dominates for large $h$ and the second one for small $h$. The minimum is reached where the derivative of $E(h)$ vanishes, at
$$h^*=\sqrt{\frac{2\,\text{eps}\,\vert f(x)\vert}{\vert f''(x)\vert}}.$$
For $f(x)=\sin x$ at $x=1$, $\vert f(x)\vert=\vert f''(x)\vert$, and we get $h^*=\sqrt{2\,\text{eps}}\approx 2\times10^{-8}$, with a minimum error of the order of $10^{-8}$. This is exactly what figure \ref{fig:error_h} shows. To the left of the minimum, the graph rises with slope $-1$, as predicted by the term $\text{eps}\vert f(x)\vert/h$; the points are scattered because the rounding error depends on how each number happens to be rounded.

The conclusions are important, and they will accompany us for the rest of the course:
\begin{itemize}
\item A smaller step does not always give a better result. With the forward difference, no more than about 8 correct digits of the derivative can be obtained, however small $h$ is.
\item Before running a computation, it is worth \emph{predicting} how its error should behave. If the result does not behave as expected, there is a mistake either in the program or in the prediction, and in both cases there is something to understand.
\item To know whether a result is correct we need to know both kinds of error: the method error, which depends on the algorithm, and the rounding error, which depends on how the arithmetic is done.
\end{itemize}
\end{paracol}

\item \textbf{Which one is correct?} The following three functions compute the roots of $ax^2+bx+c=0$ (with a positive discriminant). All three give correct results for $a=1$, $b=3$, $c=1$.
\begin{minted}{python}
import math

def raices_A(a, b, c):
    d = math.sqrt(b**2 - 4*a*c)
    return (-b + d) / (2*a), (-b - d) / (2*a)

def raices_B(a, b, c):
    d = math.sqrt(b**2 - 4*a*c)
    q = -(b + math.copysign(d, b)) / 2
    return q / a, c / q

def raices_C(a, b, c):
    d = math.sqrt(b**2 - 4*a*c)
    x1 = (-b - d) / (2*a)
    return x1, c / (a*x1)
\end{minted}

\item Explain, in terms of catastrophic cancellation, why the other two fail.
\end{enumerate}
