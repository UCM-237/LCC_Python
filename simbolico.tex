\switchcolumn
In this last chapter we are going to introduce a computing method completely different to the method described in previous chapters: Symbolic computing. So far, we have always used the computer to perform numerical computing. Variables were defined assigning them a numerical value and, after, they were used in algebraic operations or introduced in functions to obtain numerical results.

Nevertheless, in mathematics and physics, it is common practice to perform operations with variables and functions without assigning numerical values to them. A classic example is function derivation,

\switchcolumn
Departing from a function \emph{symbolic} expression, we get its derivative also expressed in a \emph{symbolic} way. This process can also be performed using a computer, which is referred to as symbolic computing, distinguishing it from numerical computing.

Sympy permite, dada una expresión simbólica, obtener una equivalente más sencilla. En general, este proceso de simplificación no es trivial ni unívoco, ya que una expresión puede admitir varias formas simplificadas. Es también posible que la expresión simbólica que deseamos simplificar, no sea simplificable.

Es interesante, sobre todo cuando se trata de expresiones obtenidas a partir de cálculos simbólicos, tratar de obtener una expresión lo más simplificada posible. La razón es que resulta mucho más fácil de entender y manipular. Sympy suministra el comando \texttt{simplify} para simplificar expresiones simbólicas. \switchcolumn
\subsection{Symbolic expression simplification}
SymPy can take a symbolic expression and generate an equivalent, simplified version. However, this process is not always straightforward or unique, as an expression may have multiple valid simplified forms. Additionally, it's possible that the expression we wish to simplify cannot be simplified at all.

Sympy supplies the command \texttt{simplify} to simplify symbolic expressions. \subsection{Errores frecuentes al mezclar Sympy y Numpy}
Sympy trabaja con números exactos (enteros, racionales, $\pi$\ldots), pero en cuanto aparece un número de coma flotante, el resultado deja de ser exacto. Los errores más frecuentes son:
\begin{itemize}
\item Usar \mintinline{python}|np.pi| en lugar de \mintinline{python}|sp.pi|: \mintinline{python}|sp.sin(np.pi)| da $1.22\cdot10^{-16}$ y \mintinline{python}|sp.sin(sp.pi)| da $0$. Del mismo modo, si integramos $\sin(\pi x)$ entre 0 y 1 con \mintinline{python}|integrate|, con \mintinline{python}|np.pi| obtenemos $0.636619772367581$ y con \mintinline{python}|sp.pi|, el resultado exacto, $2/\pi$.
\item Escribir fracciones de Python: \mintinline{python}|x**(1/3)| da \mintinline{python}|x**0.333333333333333|, porque \mintinline{python}|1/3| se calcula en coma flotante antes de llegar a Sympy. Hay que usar \mintinline{python}|sp.Rational(1, 3)| o \mintinline{python}|sp.cbrt(x)|.
\item Olvidar las hipótesis sobre las variables: \mintinline{python}|sp.sqrt(x**2)| no se simplifica a \mintinline{python}|x|, porque eso solo es cierto si $x\geq0$. Con \mintinline{python}|x = sp.symbols('x', positive=True)| sí se simplifica.
\item Creer que un resultado simbólico es siempre correcto o tiene sentido: \mintinline{python}|sp.integrate(1/x, (x, -1, 1))| devuelve \mintinline{python}|nan|, porque la integral diverge en $x=0$, aunque el integrando sea impar. Un resultado simbólico se comprueba como cualquier otro: derivando la primitiva obtenida, sustituyendo la solución en la ecuación o comparando con un cálculo numérico.
\end{itemize}
\switchcolumn
The difference, $7.5\cdot10^{-10}$, is of the order of the error expected for the central difference with $h=10^{-5}$ (section \ref{sec:paso_optimo-2}): both derivatives confirm each other. Evaluating \mintinline{python}|dg| at 2000 points with \mintinline{python}|subs| and \mintinline{python}|evalf| takes several seconds; with the function from \mintinline{python}|lambdify|, less than a millisecond (some ten thousand times less).

\subsection{Frequent mistakes when mixing Sympy and Numpy}
Sympy works with exact numbers (integers, rationals, $\pi$\ldots), but as soon as a floating-point number appears, the result is no longer exact. The most frequent mistakes are:
\begin{itemize}
\item Using \mintinline{python}|np.pi| instead of \mintinline{python}|sp.pi|: \mintinline{python}|sp.sin(np.pi)| gives $1.22\cdot10^{-16}$ and \mintinline{python}|sp.sin(sp.pi)| gives $0$. Likewise, if we integrate $\sin(\pi x)$ between 0 and 1 with \mintinline{python}|integrate|, with \mintinline{python}|np.pi| we obtain $0.636619772367581$ and with \mintinline{python}|sp.pi|, the exact result, $2/\pi$.
\item Writing Python fractions: \mintinline{python}|x**(1/3)| gives \mintinline{python}|x**0.333333333333333|, because \mintinline{python}|1/3| is computed in floating point before reaching Sympy. We must use \mintinline{python}|sp.Rational(1, 3)| or \mintinline{python}|sp.cbrt(x)|.
\item Forgetting the assumptions on the variables: \mintinline{python}|sp.sqrt(x**2)| is not simplified to \mintinline{python}|x|, because that is only true if $x\geq0$. With \mintinline{python}|x = sp.symbols('x', positive=True)| it is simplified.
\item Believing that a symbolic result is always right or meaningful: \mintinline{python}|sp.integrate(1/x, (x, -1, 1))| returns \mintinline{python}|nan|, because the integral diverges at $x=0$, even though the integrand is odd. A symbolic result is checked like any other: differentiating the primitive obtained, substituting the solution into the equation or comparing with a numerical computation.
\end{itemize}
\end{paracol}
